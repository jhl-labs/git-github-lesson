Step 6 · PR과 AI 코드 리뷰

지금까지는 혼자 main에 바로 merge 했죠. 실무에서는 Pull Request(PR)로 "이 변경을 합쳐도 될까요?"라고 묻고, 동료(또는 AI)가 리뷰한 뒤 합칩니다.

📚 시작 전 이론: Pull Request와 코드 리뷰

PR은 "코드를 합치기 전에 한 번 멈춰서 확인하는 장치"입니다. 이 Step에서는 사람 대신(또는 사람과 함께) AI 에이전트에게 리뷰를 맡기는데, 리뷰 결과를 믿을지 말지 판단하려면 PR의 구조와 AI 리뷰의 한계를 알고 있어야 해요.

Pull Request (PR)
"내 브랜치를 main에 합쳐 주세요"라는 요청. Git 명령이 아니라 GitHub의 기능이에요.
diff
두 버전의 차이. -는 지워진 줄, +는 추가된 줄. 리뷰는 diff를 읽는 일입니다.
리뷰 상태
Comment(의견만), Approve(합쳐도 좋음), Request changes(고쳐야 함) 세 가지로 남겨요.
Status check
PR에서 자동 실행된 Actions(테스트·리뷰 등)의 결과. PR 하단에 ✅/❌로 표시돼요.
브랜치 보호 (Ruleset)
"PR 없이 main에 직접 push 금지", "승인 1개 이상 필요", "검사 통과 필수" 같은 규칙을 거는 설정.
headless 모드
대화 창 없이 한 번 실행하고 결과만 출력하는 방식. claude -p "..."가 그 예예요.

PR의 흐름

  • PR은 두 브랜치의 차이(diff)를 보여주고, 줄 단위로 댓글을 달 수 있어요. 같은 브랜치에 push하면 PR에 자동으로 추가됩니다.
  • PR이 열리면 Actions가 테스트·리뷰를 자동 실행할 수 있습니다 (on: pull_request).
  • 리뷰어가 "Approve" 하면 Merge 버튼으로 합칩니다. Settings의 브랜치 규칙으로 "승인 없이는 merge 금지"도 걸 수 있어요(공개 저장소는 무료).

diff 읽는 법

diff --git a/dashboard/app.js b/dashboard/app.js
@@ -120,7 +120,8 @@ function renderTable(rows) {     ← 120번째 줄 근처가 바뀜
   const cell = document.createElement('td');
-  cell.innerHTML = value;                       ← 지운 줄
+  cell.textContent = value;                     ← 추가한 줄
+  if (typeof value === 'number') cell.className = 'num';

리뷰할 때는 "무엇이 바뀌었나"보다 "바뀐 줄이 어떤 입력을 받아 어디에 쓰이나"를 따라가 보세요. 보안 문제는 대부분 외부 입력이 위험한 곳(innerHTML, 셸 명령)에 닿을 때 생깁니다.

Merge 방법 세 가지

방법main에 남는 모습언제 쓰나
Create a merge commit브랜치의 커밋들 + 합쳤다는 merge 커밋 1개작업 이력을 그대로 보존하고 싶을 때
Squash and merge브랜치의 커밋들을 하나로 뭉친 새 커밋 1개"리뷰 반영", "오타" 같은 잔커밋을 정리할 때 (오늘 사용)
Rebase and merge브랜치의 커밋들을 main 끝에 한 줄로 다시 붙임 (merge 커밋 없음)깔끔한 일직선 이력을 원할 때

AI 리뷰: 잘하는 것과 못하는 것

잘하는 것약한 것
innerHTML·셸 인젝션·하드코딩된 비밀 같은 알려진 위험 패턴 찾기diff 밖의 맥락(다른 파일, 저장소 설정, 실제 운영 상황) 판단
빠뜨린 예외 처리, 이름·가독성 지적"이 기능이 정말 필요한가" 같은 요구사항 판단
지치지 않고 모든 PR을 같은 기준으로 확인그럴듯하지만 틀린 지적을 자신 있게 하기도 함

headless 실행과 "다른 에이전트" 리뷰

claude -p는 표준 입력(파이프로 넘긴 diff)과 프롬프트를 받아 답을 출력하고 바로 종료합니다. 사람이 대화하지 않아도 되니 Actions 같은 자동화에 넣을 수 있어요. 대신 runner에는 로그인한 사람이 없으므로 API 키를 Secret으로 넘겨야 하고, 외부 fork에서 온 PR에는 Secret이 전달되지 않아 리뷰가 실행되지 않습니다(악의적인 PR이 키를 훔치지 못하게 하는 장치). 또 코드를 작성한 세션은 자기가 쓴 맥락에 끌려가기 쉬워서, 맥락 없는 새 세션이나 다른 도구(opencode)에게 diff만 보여주는 편이 더 객관적인 리뷰가 됩니다.

✅ 실습 전 셀프 체크
  • PR이 Git의 기능이 아니라 GitHub의 기능이라는 말의 뜻을 설명할 수 있나요?
  • diff에서 -와 + 줄, @@ 줄의 의미를 말할 수 있나요?
  • Squash and merge를 하면 main에 커밋이 몇 개 생기는지 말할 수 있나요?
  • AI 리뷰 결과를 그대로 믿으면 안 되는 이유를 하나 이상 말할 수 있나요?

6-1. 기능 브랜치에서 작업하고 PR 열기

대시보드에 작은 기능을 추가해 봅시다.

git switch main && git pull
git switch -c feature/csv-download

6-2. AI 에이전트로 코드 리뷰하기 (CLI)

Claude Code의 -p(print) 옵션은 대화 창 없이 한 번 질문하고 답만 출력하는 headless 모드예요. 파이프(|)로 PR의 diff를 넘겨주면 리뷰어처럼 동작합니다. 같은 방식으로 다른 에이전트 CLI(opencode)도 쓸 수 있어요. 

# PR 번호가 1번이라면
gh pr diff 1 | claude -p "이 PR diff를 시니어 개발자처럼 한국어로 리뷰해줘.
보안(XSS, 비밀 정보 노출, 워크플로우 인젝션), 버그, 가독성 순서로
'🔴 꼭 고칠 것 / 🟡 고치면 좋은 것 / 🟢 잘한 점' 형식으로, 파일:줄 위치와 수정 예시를 포함해줘." > review.md

cat review.md
gh pr comment 1 --body-file review.md   # 리뷰 결과를 PR 댓글로 남기기

opencode는 터미널용 오픈소스 AI 코딩 에이전트입니다. run 하위 명령으로 비대화형 실행을 해요.

opencode run "gh pr diff 1 명령으로 PR 1번의 변경 사항을 확인하고 한국어로 코드 리뷰해줘.
보안, 버그, 가독성 관점에서 꼭 고칠 것 / 고치면 좋은 것 / 잘한 점으로 나눠서 정리해줘." > review.md

gh pr comment 1 --body-file review.md

이미 Claude Code를 열어 두었다면 그냥 부탁해도 됩니다.

PR 1번을 gh pr diff 로 읽고 코드 리뷰해줘. 지적 사항은 gh pr review 1 --comment 로 PR에 남겨줘.
✦ 왜 "다른 AI"에게 리뷰를 맡길까? 코드를 짠 AI 세션은 자기 결과를 좋게 보는 경향이 있어요. 새 세션(claude -p)이나 다른 도구(opencode)로 맥락 없이 diff만 보게 하면 사람 리뷰어처럼 더 객관적인 지적이 나옵니다. 그래도 최종 판단은 사람이 합니다. AI의 지적이 틀릴 수도 있어요.

6-3. PR이 열릴 때마다 자동 리뷰 (Actions)

CLI 리뷰를 워크플로우로 옮기면 PR마다 자동으로 리뷰 댓글이 달립니다.

  1. API 키를 Secret으로 등록 — Anthropic Console에서 키를 발급받아 저장소에 등록 (키는 화면·코드에 노출하지 마세요) 
    gh secret set ANTHROPIC_API_KEY   # 실행 후 키를 붙여넣기 (입력은 화면에 보이지 않음)
  2. 워크플로우 만들기
  3. PR에 push 해서 확인 — 워크플로우 파일을 PR 브랜치에 커밋·push 하면 바로 그 PR에서 리뷰가 실행됩니다.
참고 Anthropic이 제공하는 공식 Action(anthropics/claude-code-action)을 쓰면 PR 댓글에서 @claude를 불러 대화형으로 수정을 요청할 수도 있어요. 오늘은 원리를 보기 위해 CLI를 직접 호출했습니다.

6-4. 리뷰 연습: 위험한 코드 찾기

AI 리뷰가 정말 잡아내는지 시험해 봅시다. 새 브랜치에서 아래 두 변경을 일부러 넣고 PR을 열어 보세요. (리뷰 확인 후 PR은 merge하지 말고 닫습니다.)

// dashboard/app.js — 시트 이름을 제목에 표시 (❌ XSS: 엑셀 시트 이름에 <img src=x onerror=alert(1)> 를 넣으면?)
document.getElementById('dash-title').innerHTML = config.title + ' - ' + state.sheet.name;
# .github/workflows/excel-to-dashboard.yml 의 steps 에 추가 (❌ 스크립트 인젝션)
      - name: 이슈 제목 기록
        shell: bash
        run: echo "처리 중: ${{ github.event.issue.title }}"
  • AI 리뷰가 innerHTML 사용을 XSS 위험으로 지적했다
  • AI 리뷰가 이슈 제목의 직접 삽입을 인젝션 위험으로 지적했다
  • 지적에 따라 고친 코드(textContent, env 전달)를 이해했다
  • 연습용 PR을 merge 하지 않고 닫았다 (gh pr close 번호)

6-5. 리뷰 반영 후 Merge

# 지적 사항을 고친 뒤 같은 브랜치에 push → PR에 자동 반영
git add . && git commit -m "리뷰 반영: CSV 이스케이프 보강" && git push

gh pr merge 1 --squash --delete-branch   # 여러 커밋을 하나로 합쳐 main에 병합
git switch main && git pull

main에 합쳐지면 deploy-dashboard 워크플로우가 실행되어 Pages에도 CSV 버튼이 생깁니다. 코드 리뷰 → 병합 → 자동 배포, 실무 개발 흐름 한 바퀴를 완주했어요! 🎉

🏁 마무리: 리뷰 → 병합 → 자동 배포, 한 바퀴 완주

대시보드에 CSV 다운로드 기능을 기능 브랜치에서 만들고 PR로 올렸습니다. claude -p·opencode로 diff를 리뷰받고, PR마다 자동으로 리뷰 댓글을 다는 워크플로우까지 붙였어요. 리뷰를 반영해 Squash merge하자 Pages가 자동으로 다시 배포됐습니다.

✅ 이번 Step에서 한 일

  1. 기능 브랜치에서 작업하고 PR 열기 feature/csv-download에서 CSV 버튼을 만들고 gh pr create로 PR을 열었어요.
  2. CLI로 AI 리뷰 gh pr diff 1 | claude -p "..."(또는 opencode)로 리뷰를 받아 gh pr comment로 PR에 남겼어요.
  3. 자동 리뷰 워크플로우 ANTHROPIC_API_KEY를 Secret으로 등록하고 ai-review.yml을 만들어 PR마다 리뷰가 달리게 했어요.
  4. 리뷰 연습 innerHTML XSS와 이슈 제목 인젝션을 일부러 넣은 PR로 AI가 잡아내는지 확인하고, 그 PR은 merge하지 않고 닫았어요.
  5. 리뷰 반영 후 Merge 고친 코드를 같은 브랜치에 push하고 gh pr merge 1 --squash --delete-branch로 합쳤어요.

📦 만들어진 결과물

  • 대시보드의 "CSV 다운로드" 버튼 (dashboard/ 변경, UTF-8 BOM·CSV 이스케이프)
  • .github/workflows/ai-review.yml, .github/review-prompt.md — PR 자동 리뷰
  • 저장소 Secret ANTHROPIC_API_KEY
  • 리뷰 댓글이 달린 PR과 main의 squash 커밋 1개, 닫힌 연습용 PR
  • deploy-dashboard 워크플로우로 다시 배포된 Pages 대시보드

💡 핵심 정리

PR은 GitHub 기능
합치기 전에 멈춰서 diff를 보고 의견을 나누는 장치. 같은 브랜치에 push하면 PR에 자동 반영돼요.
diff 리뷰
바뀐 줄이 어떤 입력을 받아 어디에 쓰이는지 따라가세요. 보안 문제는 외부 입력이 innerHTML·셸 명령에 닿을 때 생깁니다.
headless AI 리뷰
claude -p는 한 번 답하고 끝나서 자동화에 넣기 좋아요. runner에서는 API 키를 Secret으로 넘기고, 외부 fork PR은 건너뜁니다.
다른 AI, 최종 판단은 사람
맥락 없는 새 세션이나 다른 도구가 더 객관적이지만, AI도 틀린 지적을 자신 있게 할 수 있어요.
Squash and merge
브랜치의 여러 커밋을 하나로 뭉쳐 main에 커밋 1개로 남깁니다.

🔍 확인하고 넘어가기

  • PR에 "🤖 AI 코드 리뷰" 댓글이 자동으로 달렸다
  • PR이 merge되고 main에 squash 커밋이 1개 생겼다
  • Pages 대시보드에서 CSV 다운로드 버튼이 동작하고, 엑셀로 열어도 한글이 깨지지 않는다
  • 연습용 PR은 merge하지 않고 닫았다
  • AI 리뷰 결과를 그대로 믿으면 안 되는 이유를 말할 수 있다
