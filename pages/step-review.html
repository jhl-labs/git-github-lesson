Step 6 · PR과 AI 코드 리뷰

지금까지는 혼자 main에 바로 merge 했죠. 실무에서는 Pull Request(PR)로 "이 변경을 합쳐도 될까요?"라고 묻고, 동료(또는 AI)가 리뷰한 뒤 합칩니다.

잠깐 이론: Pull Request

  • PR은 GitHub의 기능이에요(Git 명령이 아닙니다). 두 브랜치의 차이(diff)를 보여주고, 줄 단위로 댓글을 달 수 있어요.
  • PR이 열리면 Actions가 테스트·리뷰를 자동 실행할 수 있습니다 (on: pull_request).
  • 리뷰어가 "Approve" 하면 Merge 버튼으로 합칩니다. Settings에서 "리뷰 승인 없이는 merge 금지" 규칙(Branch protection)도 걸 수 있어요.

6-1. 기능 브랜치에서 작업하고 PR 열기

대시보드에 작은 기능을 추가해 봅시다.

git switch main && git pull
git switch -c feature/csv-download

6-2. AI 에이전트로 코드 리뷰하기 (CLI)

Claude Code의 -p(print) 옵션은 대화 창 없이 한 번 질문하고 답만 출력하는 headless 모드예요. 파이프(|)로 PR의 diff를 넘겨주면 리뷰어처럼 동작합니다. 같은 방식으로 다른 에이전트 CLI(opencode)도 쓸 수 있어요. 

# PR 번호가 1번이라면
gh pr diff 1 | claude -p "이 PR diff를 시니어 개발자처럼 한국어로 리뷰해줘.
보안(XSS, 비밀 정보 노출, 워크플로우 인젝션), 버그, 가독성 순서로
'🔴 꼭 고칠 것 / 🟡 고치면 좋은 것 / 🟢 잘한 점' 형식으로, 파일:줄 위치와 수정 예시를 포함해줘." > review.md

cat review.md
gh pr comment 1 --body-file review.md   # 리뷰 결과를 PR 댓글로 남기기

opencode는 터미널용 오픈소스 AI 코딩 에이전트입니다. run 하위 명령으로 비대화형 실행을 해요.

opencode run "gh pr diff 1 명령으로 PR 1번의 변경 사항을 확인하고 한국어로 코드 리뷰해줘.
보안, 버그, 가독성 관점에서 꼭 고칠 것 / 고치면 좋은 것 / 잘한 점으로 나눠서 정리해줘." > review.md

gh pr comment 1 --body-file review.md

이미 Claude Code를 열어 두었다면 그냥 부탁해도 됩니다.

PR 1번을 gh pr diff 로 읽고 코드 리뷰해줘. 지적 사항은 gh pr review 1 --comment 로 PR에 남겨줘.
✦ 왜 "다른 AI"에게 리뷰를 맡길까? 코드를 짠 AI 세션은 자기 결과를 좋게 보는 경향이 있어요. 새 세션(claude -p)이나 다른 도구(opencode)로 맥락 없이 diff만 보게 하면 사람 리뷰어처럼 더 객관적인 지적이 나옵니다. 그래도 최종 판단은 사람이 합니다. AI의 지적이 틀릴 수도 있어요.

6-3. PR이 열릴 때마다 자동 리뷰 (Actions)

CLI 리뷰를 워크플로우로 옮기면 PR마다 자동으로 리뷰 댓글이 달립니다.

  1. API 키를 Secret으로 등록 — Anthropic Console에서 키를 발급받아 저장소에 등록 (키는 화면·코드에 노출하지 마세요) 
    gh secret set ANTHROPIC_API_KEY   # 실행 후 키를 붙여넣기 (입력은 화면에 보이지 않음)
  2. 워크플로우 만들기
  3. PR에 push 해서 확인 — 워크플로우 파일을 PR 브랜치에 커밋·push 하면 바로 그 PR에서 리뷰가 실행됩니다.
참고 Anthropic이 제공하는 공식 Action(anthropics/claude-code-action)을 쓰면 PR 댓글에서 @claude를 불러 대화형으로 수정을 요청할 수도 있어요. 오늘은 원리를 보기 위해 CLI를 직접 호출했습니다.

6-4. 리뷰 연습: 위험한 코드 찾기

AI 리뷰가 정말 잡아내는지 시험해 봅시다. 새 브랜치에서 아래 두 변경을 일부러 넣고 PR을 열어 보세요. (리뷰 확인 후 PR은 merge하지 말고 닫습니다.)

// dashboard/app.js — 시트 이름을 제목에 표시 (❌ XSS: 엑셀 시트 이름에 <img src=x onerror=alert(1)> 를 넣으면?)
document.getElementById('dash-title').innerHTML = config.title + ' - ' + state.sheet.name;
# .github/workflows/excel-to-dashboard.yml 의 steps 에 추가 (❌ 스크립트 인젝션)
      - name: 이슈 제목 기록
        shell: bash
        run: echo "처리 중: ${{ github.event.issue.title }}"
  • AI 리뷰가 innerHTML 사용을 XSS 위험으로 지적했다
  • AI 리뷰가 이슈 제목의 직접 삽입을 인젝션 위험으로 지적했다
  • 지적에 따라 고친 코드(textContent, env 전달)를 이해했다
  • 연습용 PR을 merge 하지 않고 닫았다 (gh pr close 번호)

6-5. 리뷰 반영 후 Merge

# 지적 사항을 고친 뒤 같은 브랜치에 push → PR에 자동 반영
git add . && git commit -m "리뷰 반영: CSV 이스케이프 보강" && git push

gh pr merge 1 --squash --delete-branch   # 여러 커밋을 하나로 합쳐 main에 병합
git switch main && git pull

main에 합쳐지면 deploy-dashboard 워크플로우가 실행되어 Pages에도 CSV 버튼이 생깁니다. 코드 리뷰 → 병합 → 자동 배포, 실무 개발 흐름 한 바퀴를 완주했어요! 🎉
