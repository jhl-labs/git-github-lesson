Step 5 · 이슈로 엑셀 올려 전체 실행

드디어 전체 흐름을 돌려 봅니다. 엑셀을 이슈에 올리고, Actions가 일하는 모습을 실시간으로 지켜보세요.

📚 시작 전 이론: 이슈 한 건이 자동화가 되기까지

이번 Step은 새 코드를 만들지 않고 지금까지 만든 것을 실제로 돌려 보는 단계입니다. 버튼 하나 누르면 끝나는 것처럼 보이지만, 중간에 무엇이 오가는지 알아야 실패했을 때 로그를 읽고 고칠 수 있어요.

이슈 폼 (issue form)
.github/ISSUE_TEMPLATE/*.yml로 만든 입력 양식. 제출하면 결국 마크다운 본문 한 덩어리로 저장돼요.
첨부 URL
이슈에 파일을 끌어다 놓으면 GitHub이 파일을 보관하고 본문에 https://github.com/user-attachments/files/... 링크를 넣어 줍니다.
이벤트 페이로드
이벤트와 함께 워크플로우에 전달되는 JSON 데이터. github.event로 읽어요.
Run · Job · Step 로그
워크플로우 1회 실행 = run. run 안의 job마다, job 안의 step마다 로그가 따로 남습니다.
Annotation
스크립트가 ::warning::/::error:: 형식으로 출력하면 실행 요약 화면에 노란·빨간 알림으로 표시돼요.
멱등성 (idempotency)
같은 작업을 여러 번 실행해도 결과가 똑같이 유지되는 성질. 자동화는 "다시 돌려도 안전한가"가 중요해요.

이슈 폼은 결국 마크다운이에요

예쁜 입력 칸으로 보이지만, 제출된 이슈 본문은 이렇게 생긴 텍스트입니다. 그래서 다운로드 스크립트는 본문에서 .xlsx 링크를 글자로 찾아 내요.

### 엑셀 파일

[sales-2026-h1.xlsx](https://github.com/user-attachments/files/<번호>/sales-2026-h1.xlsx)

### 메모 (선택)

_No response_

파일 업로드가 끝나기 전에 Submit 하면 링크 대신 "Uploading…" 문구가 남아 다운로드가 실패해요. 그리고 공개 저장소의 첨부 파일은 링크만 알면 누구나 내려받을 수 있습니다. 이슈를 지워도 이미 퍼진 링크까지 회수된다고 기대하면 안 돼요.

워크플로우가 받는 이벤트 페이로드

이슈가 열리면 GitHub은 대략 아래 같은 JSON을 워크플로우에 넘깁니다. if: 조건과 env:에서 쓰는 값이 전부 여기서 나와요.

{
  "action": "opened",
  "issue": {
    "number": 3,
    "title": "[EXCEL] 상반기 매출",
    "body": "### 엑셀 파일\n\n[sales-2026-h1.xlsx](https://github.com/user-attachments/...)",
    "user": { "login": "you" },
    "author_association": "OWNER"
  },
  "repository": { "name": "excel-dashboard", "default_branch": "main" },
  "sender": { "login": "you" }
}

실행 결과 읽는 법

표시의미
🟡 Queued / In progressrunner(VM)를 배정받는 중이거나 실행 중. Windows는 준비 시간이 더 걸려요
✅ Success모든 step 성공. 경고(annotation)가 있어도 성공일 수 있어요
❌ Failure어느 step이 0이 아닌 종료 코드로 끝남. 빨간 step부터 로그를 펼쳐 보세요
⊘ Skippedjob의 if: 조건이 거짓 → 실행 자체를 안 함 (실패가 아니에요)

로그는 위에서부터가 아니라 빨간 X가 붙은 step의 마지막 몇 줄부터 읽는 게 요령입니다. 터미널에서는 gh run view <id> --log-failed로 실패한 부분만 볼 수 있어요.

다시 실행(Re-run)의 함정

Re-run jobs는 처음 이벤트와 같은 페이로드, 같은 커밋으로 다시 돌립니다. 그래서 일시적인 네트워크 오류에는 좋지만, 코드를 고쳐 push한 뒤 Re-run 하면 고치기 전 코드가 다시 실행돼요. 수정 사항을 반영하려면 새 이슈를 올려야 합니다.

다시 돌려도 안전한가: 멱등성과 동시 실행

  • 같은 엑셀을 두 번 올려도 data.json 내용이 같으면 배포 스크립트가 "변경 없음"으로 커밋하지 않고 끝나요.
  • 이슈 두 개가 동시에 올라오면 두 runner가 동시에 docs에 push하다 충돌할 수 있어요. 워크플로우의 concurrency 그룹이 이를 한 번에 하나씩 줄 세웁니다.
  • 데이터 변경은 전부 커밋으로 남으니, 잘못 올렸다면 docs 브랜치를 이전 커밋으로 되돌릴 수 있어요.
✅ 실습 전 셀프 체크
  • 워크플로우가 이슈 본문에서 첨부 파일을 어떻게 찾는지 설명할 수 있나요?
  • Actions 탭에 "Skipped"가 보이면 무엇부터 확인해야 하는지 말할 수 있나요?
  • 코드를 고친 뒤 Re-run을 눌러도 같은 오류가 나는 이유를 설명할 수 있나요?
  • concurrency가 없으면 어떤 문제가 생길 수 있는지 말할 수 있나요?

5-1. 엑셀 업로드

  1. 샘플 엑셀 준비 — sales-2026-h1.xlsx 또는 직접 만든 엑셀 (민감 정보 금지!)
  2. Issues → New issue → "📊 엑셀 데이터 업로드" 선택
  3. 제목을 [EXCEL] 상반기 매출처럼 쓰고, 파일 칸에 엑셀을 끌어다 놓기 — 업로드가 끝나면 [sales-2026-h1.xlsx](https://github.com/user-attachments/files/...) 형태의 링크가 생깁니다.
  4. Submit new issue

5-2. Actions 지켜보기

Actions 탭으로 가면 노란 점(실행 중)이 돌고 있을 거예요. 클릭해서 각 단계의 로그를 펼쳐 보세요. 터미널에서도 볼 수 있습니다.

gh run list --limit 5
gh run watch          # 실행 중인 워크플로우를 실시간으로

성공하면 이슈에 봇의 댓글이 달리고 이슈가 닫힙니다. 1~2분 뒤 Pages 주소를 새로고침하고 비밀번호를 입력하세요. 🎉

⏱ 생각보다 오래 걸리죠? GitHub이 job마다 실제 Windows 서버(VM)를 새로 준비하고, 그 위에서 파이썬 설치·xlwings 시도·변환을 하느라 보통 2~4분이 걸립니다. 같은 일을 Linux + openpyxl로 하면 1분이 채 안 걸려요. 이 차이는 마지막 장에서 숫자로 비교합니다.

5-3. docs 브랜치에서 일어난 일 확인

git fetch
git log --oneline origin/docs   # "data: 이슈 #N 엑셀 반영" 커밋이 보입니다
git show --stat origin/docs     # 어떤 파일이 바뀌었는지

봇도 결국 Git 커밋을 한 거예요. 데이터가 바뀐 이력이 커밋으로 남으니, 잘못된 엑셀을 올렸다면 이전 커밋으로 되돌릴 수도 있습니다.

안 될 때: 트러블슈팅

증상원인과 해결
Actions가 아예 실행되지 않음제목이 [EXCEL]로 시작하는지, 내가 저장소 소유자/협업자인지 확인. Actions 탭에 "skipped"로 보이면 if: 조건 때문입니다.
첨부 파일을 찾지 못함업로드가 끝나기 전에 Submit 했을 수 있어요. 본문에 .xlsx 링크가 있는지 확인 후 새 이슈로 다시 올리세요.
xlwings 실패 … openpyxl로 대체 경고정상입니다. GitHub-hosted Windows runner에 Excel이 없어 대체된 것이고, 데이터는 openpyxl로 변환됐어요.
push 단계에서 403Settings → Actions → General → Workflow permissions를 "Read and write"로, 또는 워크플로우의 permissions: contents: write 확인
Pages가 404 · 데이터가 안 바뀜Settings → Pages의 Source가 GitHub Actions인지, 실행 화면에서 deploy job까지 초록색인지 확인. "Deploy from a branch"로 두면 봇(GITHUB_TOKEN)의 push로는 배포가 시작되지 않아요.
대시보드가 옛날 데이터브라우저 강력 새로고침(Ctrl+Shift+R). Pages CDN 캐시로 최대 몇 분 늦을 수 있어요.

막히면 실패 로그를 Claude Code에게 그대로 보여주세요.
