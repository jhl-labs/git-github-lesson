전체 구조

왜 이런 구조일까?

요구 사항사용하는 GitHub 기능배우는 개념
엑셀 파일을 쉽게 올리고 싶다Issues (파일 첨부 + 이슈 템플릿)이벤트(이슈 생성)가 자동화를 깨운다
엑셀을 사람 손 없이 변환하고 싶다Actions + Windows runner + xlwings워크플로우, 트리거, runner, 권한
변환 결과를 버전 관리하고 싶다Git (docs 브랜치에 커밋)브랜치의 다른 용도: 배포용 브랜치
웹에서 보고 싶다Pages (docs 브랜치를 웹으로 서빙)정적 호스팅
아무나 보면 안 된다비밀번호 화면 (JavaScript)…그런데 이게 진짜 보안일까? → 마지막 장
🤔 왜 Windows + xlwings? xlwings는 실제 Microsoft Excel 프로그램을 원격 조종해서 파일을 읽습니다. 수식·매크로가 많은 회사 엑셀을 "엑셀이 보여주는 그대로" 읽을 수 있다는 장점이 있지만, Excel이 설치된 Windows(또는 macOS)가 필요합니다. 이번 실습은 일부러 이 구조를 택해 Actions의 OS 선택을 경험해 보고, 마지막 장에서 "실무라면 Linux에서 병렬로 처리하는 게 왜 더 나은지" 비교합니다.

최종 저장소 구조

excel-dashboard/
├── .github/
│   ├── ISSUE_TEMPLATE/excel-upload.yml   ← "엑셀 업로드" 이슈 양식
│   ├── workflows/
│   │   ├── excel-to-dashboard.yml        ← 이슈 → 변환 → docs 브랜치 (Windows)
│   │   ├── deploy-dashboard.yml          ← 화면 코드 변경 시 재배포 (Linux)
│   │   └── ai-review.yml                 ← PR 자동 코드 리뷰 (Linux)
│   └── review-prompt.md
├── scripts/
│   ├── excel_to_json.py                  ← 엑셀 → JSON 변환기
│   ├── fetch_attachment.py               ← 이슈 첨부 파일 다운로드
│   ├── publish_docs.sh                   ← docs 브랜치에 반영
│   └── requirements.txt
├── dashboard/                            ← Pages로 서빙될 화면 (index.html, app.js, style.css, config.js)
├── tests/test_excel_to_json.py
└── CLAUDE.md                             ← Claude Code에게 주는 프로젝트 설명서
📦 정답 예시가 준비되어 있어요 이 사이트 저장소의 templates/excel-dashboard/에 강사가 검증한 완성 코드가 있습니다. Claude Code의 결과물이 이상할 때 비교해 보세요. 단, 먼저 직접 프롬프트로 만들어 보는 것이 이 과정의 핵심입니다.
