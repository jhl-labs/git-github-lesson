Step 1 · GitHub 저장소와 Claude Code

GitHub의 핵심 개념을 훑어보고, 실습용 저장소를 만든 뒤 Claude Code를 연결합니다.

📚 시작 전 이론: Git·GitHub·인증·Claude Code

이 Step에서는 진짜 GitHub에 저장소를 만들고, 내 컴퓨터와 연결하고, AI 코딩 도구를 붙입니다. 명령을 따라 치기 전에 "내 컴퓨터와 GitHub이 어떤 관계인지"와 "GitHub이 나를 어떻게 알아보는지"를 먼저 정리해 둡시다.

Git
내 컴퓨터에서 돌아가는 버전 관리 프로그램. 인터넷 없이도 커밋·브랜치가 다 됩니다.
GitHub
Git 저장소를 인터넷에 보관해 주는 서비스(웹사이트). 여기에 Issues·PR·Actions·Pages 같은 협업 기능이 얹혀 있어요.
저장소 (repository)
프로젝트 파일 + 전체 커밋 기록이 담긴 단위. 내 컴퓨터에 하나(로컬), GitHub에 하나(원격)가 있습니다.
원격 (remote) · origin
로컬 저장소가 기억하는 "상대 저장소 주소"의 별명. clone하면 원본 주소가 자동으로 origin이라는 이름으로 등록돼요.
gh
GitHub 공식 명령줄 도구. 저장소 생성·이슈·PR·Actions 로그 보기를 터미널에서 할 수 있어요. (git과는 다른 프로그램!)
CLAUDE.md
Claude Code가 세션을 시작할 때 자동으로 읽는 프로젝트 설명서. 매번 반복할 설명·규칙을 여기에 적어 둡니다.

Git과 GitHub은 다른 것

git commit은 내 컴퓨터 안에서만 일어납니다. GitHub에는 git push를 해야 비로소 올라가요. 반대로 GitHub 웹에서 생긴 변화(다른 사람의 커밋, 봇의 커밋)는 git pull/git fetch를 해야 내 컴퓨터에 내려옵니다. Step 5에서 봇이 만든 docs 브랜치를 git fetch로 확인하는 것도 이 때문이에요. 

내 컴퓨터 (로컬 저장소)                     GitHub (원격 저장소 = origin)
 ┌──────────────────────┐   git push  →   ┌──────────────────────────────┐
 │ 작업 폴더 + .git/     │                 │ github.com/<아이디>/excel-dashboard │
 │ (커밋 기록)           │   ← git pull    │ + Issues · PR · Actions · Pages │
 └──────────────────────┘   ← git clone   └──────────────────────────────┘

Public과 Private

Public 저장소는 전 세계 누구나 코드와 이슈(첨부 파일 포함)를 볼 수 있고, Private은 초대한 사람만 볼 수 있어요. 무료 계정에서 GitHub Pages를 쓰려면 저장소가 Public이어야 합니다(Private 저장소의 Pages는 유료 플랜 기능). 또 Public 저장소는 GitHub이 제공하는 표준 runner를 무료로 쓸 수 있고, Private 저장소는 계정별 무료 사용량(분) 한도가 있어요. 그래서 오늘 실습 저장소는 Public으로 만들고, 민감한 실제 데이터는 절대 올리지 않습니다.

인증: GitHub은 내가 누군지 어떻게 알까?

push는 "내 저장소에 쓰기"라서 GitHub이 본인 확인을 합니다. 2021년부터 Git 작업에 계정 비밀번호는 쓸 수 없어요. 대신 아래 중 하나를 씁니다.

방식어떻게 동작하나이번 실습에서
gh auth login브라우저로 로그인하면 gh가 토큰을 받아 보관하고, Git이 HTTPS로 push할 때도 그 토큰을 쓰도록 연결해 줌추천. 준비물 체크에서 이미 했어요
HTTPS + 개인 액세스 토큰(PAT)GitHub 설정에서 만든 토큰을 비밀번호 칸에 입력. 권한·만료일을 정할 수 있음gh를 못 쓸 때의 대안
SSH 키내 컴퓨터의 개인 키 + GitHub에 등록한 공개 키로 확인. 주소가 git@github.com:... 형태이미 SSH를 쓰고 있다면 그대로 OK

git remote -v로 보이는 주소가 https://인지 git@인지에 따라 어떤 인증을 쓰는지가 정해져요. push가 403/Permission denied로 실패한다면 대부분 이 인증 문제입니다. gh auth status로 먼저 확인하세요.

Claude Code는 저장소를 어떻게 이해할까?

  • 실행한 폴더가 작업 범위예요. 그래서 반드시 저장소 폴더 안에서 claude를 실행합니다.
  • 처음부터 모든 파일을 외우고 있지 않아요. 필요할 때 파일을 찾아 읽고, 명령(git, python, gh…)을 실행하고, 파일을 고칩니다. 명령 실행·파일 수정 전에는 허락을 물어봐요.
  • 새 세션은 지난 대화를 기억하지 못합니다. 그래서 프로젝트 목표·폴더 구조·규칙을 CLAUDE.md에 적어 두면, 세션마다 그걸 먼저 읽고 일관되게 작업해요.
  • GitHub 웹의 상태(이슈, Actions 결과)는 저절로 알지 못합니다. gh 명령을 실행시켜 읽게 하거나, 로그를 붙여넣어 줘야 해요.
✅ 실습 전 셀프 체크
  • "커밋했는데 GitHub에 안 보여요"라는 질문에 원인을 설명할 수 있나요?
  • origin이 무엇이고 언제 자동으로 생기는지 말할 수 있나요?
  • push할 때 GitHub이 나를 확인하는 방법 두 가지 이상을 말할 수 있나요?
  • CLAUDE.md를 먼저 만드는 이유를 설명할 수 있나요?

GitHub 한눈에 보기

GitHub는 Git 저장소를 인터넷에 올려두는 곳이자, 그 위에서 협업하기 위한 도구 모음입니다. 오늘 쓸 기능은 다섯 가지예요.

📁

Repository

프로젝트 하나 = 저장소 하나. 코드와 전체 커밋 기록이 들어 있어요.

🐛

Issues

할 일·버그·요청을 적는 게시판. 오늘은 엑셀 업로드 창구로 씁니다.

🔀

Pull Request

"내 브랜치를 main에 합쳐 주세요" 요청. 여기서 코드 리뷰를 해요.

⚙️

Actions

이벤트가 생기면 자동으로 스크립트를 실행하는 로봇.

🌐

Pages

저장소 파일을 그대로 웹사이트로 공개.

1-1. 저장소 만들기

원하는 작업 폴더에서 실행하세요. 저장소 생성 + 내 컴퓨터로 clone까지 한 번에 됩니다.

gh repo create excel-dashboard --public --clone --add-readme --description "엑셀 → GitHub Actions → Pages 대시보드 실습"
cd excel-dashboard
git log --oneline   # Initial commit 하나가 보이면 성공
  1. github.com 우측 상단 + → New repository
  2. 이름 excel-dashboard, Public, "Add a README file" 체크 → Create
  3. 초록색 Code 버튼에서 HTTPS 주소 복사 후 clone 
    git clone https://github.com/<내아이디>/excel-dashboard.git
cd excel-dashboard
🔗 Git 실습실과 연결해 보세요 방금 한 일은 실습실 미션 7(clone으로 팀 프로젝트 참여)의 git clone과 같아요. 원격(GitHub)에 저장소가 먼저 생기고, 그걸 내 컴퓨터로 복사했습니다. git remote -v를 쳐 보면 origin이 GitHub 주소로 이미 연결되어 있을 거예요.

1-2. GitHub 화면 익히기: 저장소 · 설정 · 권한

방금 만든 저장소를 브라우저로 열어 보세요(gh repo view --web). 앞으로 모든 Step이 이 화면에서 일어나니, 어디에 무엇이 있는지 한 번 훑고 갑니다.

  • 🕒 커밋 수 링크 — 커밋 기록(git log의 웹 버전). 커밋을 누르면 바뀐 줄(diff)이 보입니다.

  • 파일을 열면 History(그 파일의 변경 이력)와 Blame(줄마다 누가 언제 바꿨는지)을 볼 수 있어요.

권한: 누가 무엇을 할 수 있나

개인 계정 저장소는 단순해요. 주인(owner) 한 명과, 주인이 Settings → Collaborators → Add people로 초대한 협업자(collaborator)가 있고, 협업자는 초대를 수락해야 push할 수 있습니다(설정 변경은 주인만). 조직(Organization) 저장소는 사람·팀마다 아래 역할 중 하나를 줍니다.

역할할 수 있는 일이런 사람에게
Read코드 보기·clone, 이슈·PR 작성과 댓글구경만 하는 사람
TriageRead + 이슈·PR 정리(라벨, 담당자, 닫기). 코드 push는 불가이슈 관리 담당
Write브랜치 push, PR 병합, 이슈·PR 관리개발자 (이 과정의 gate job은 Write 이상만 통과)
MaintainWrite + 일부 설정(Features 등). 위험한 설정은 불가프로젝트 관리자
Admin모든 설정(공개 범위, 권한, Secrets, 삭제)저장소 책임자
⚠️ Public 저장소에서 "누구나" 할 수 있는 것 로그인한 사람이라면 누구나 코드 보기·clone·fork, 이슈 열기, (fork를 통한) PR 열기를 할 수 있어요. push와 설정 변경만 막혀 있습니다. 그래서 Step 3의 워크플로우는 "이슈를 연 사람이 이 저장소에 쓰기 권한이 있는지"를 먼저 확인합니다.

공개 범위는 나중에 바꿀 수 있어요

Settings → General → Danger Zone → Change repository visibility에서 Public ↔ Private을 바꿀 수 있습니다. 다만 무료 계정에서 Private으로 바꾸면 GitHub Pages를 쓸 수 없게 되고(Pages는 유료 플랜부터 Private 지원), Actions도 무료 사용량을 차감하기 시작해요. 한 번 공개됐던 내용은 이미 누군가 복사했을 수 있으니, 비밀이 섞였다면 공개 범위를 바꾸는 것만으로는 부족합니다(비밀 값 자체를 교체해야 해요).

1-3. Claude Code 시작하기

저장소 폴더 안에서 Claude Code를 실행합니다. Claude Code는 현재 폴더의 파일을 읽고, 명령을 실행하고, 파일을 고칠 수 있는 AI 코딩 도구예요.

claude
✦ 바이브 코딩 3원칙
  1. 목표와 제약을 구체적으로 — "대시보드 만들어줘"보다 "data/data.json을 읽어 KPI 카드·막대 차트·표를 보여주는 정적 페이지"가 훨씬 낫습니다.
  2. 작게 나눠서 — 한 번에 전부 시키지 말고 Step마다 하나씩. 각 Step이 끝나면 커밋해서 되돌아갈 지점을 만듭니다.
  3. 결과는 반드시 확인 — Claude가 보여주는 변경 내용(diff)을 읽고, 직접 실행해 보고, 이상하면 그대로 말해 주세요.

1-4. 첫 프롬프트: 프로젝트 설명서(CLAUDE.md) 만들기

CLAUDE.md는 Claude Code가 매번 읽는 "프로젝트 설명서"입니다. 이걸 먼저 만들어 두면 이후 프롬프트가 훨씬 짧아져요.

Claude가 만든 CLAUDE.md를 열어 읽어 본 뒤, 마음에 들면 커밋하고 push 합니다. 실습실에서 했던 그대로예요.

git status
git add CLAUDE.md
git commit -m "프로젝트 설명서 추가"
git push
💡 Claude Code에게 커밋을 맡겨도 돼요 "변경 사항 커밋하고 push 해줘"라고 말하면 Claude가 git add → git commit → git push를 대신 실행합니다. 단, 처음에는 직접 쳐 보면서 실습실에서 배운 개념과 연결해 보세요.

🏁 마무리: 저장소와 AI 작업 환경 준비 완료

진짜 GitHub에 실습 저장소를 만들어 내 컴퓨터로 clone하고, 그 폴더에서 Claude Code를 실행했습니다. 그리고 첫 프롬프트로 프로젝트 설명서 CLAUDE.md를 만들어 커밋·push까지 마쳤어요. 이제 앞으로의 모든 Step이 이 저장소 위에서 진행됩니다.

✅ 이번 Step에서 한 일

  1. GitHub 기능 다섯 가지 훑어보기 Repository · Issues · Pull Request · Actions · Pages가 각각 이번 프로젝트에서 맡을 역할을 확인했어요.
  2. 저장소 만들기 + clone gh repo create ... --public --clone(또는 웹 화면)으로 Public 저장소를 만들고 내 컴퓨터로 가져왔어요.
  3. Claude Code 시작 저장소 폴더 안에서 claude를 실행하고 바이브 코딩 3원칙을 익혔어요.
  4. CLAUDE.md 만들기 서비스 개요·폴더 구조·규칙을 담은 프롬프트로 프로젝트 설명서를 만들고 직접 읽어 봤어요.
  5. 커밋 & push git add → git commit → git push로 GitHub에 첫 변경을 올렸어요.

  • 내 컴퓨터의 로컬 저장소 excel-dashboard/ — origin이 GitHub 주소로 연결됨
  • CLAUDE.md — Claude Code가 세션마다 먼저 읽는 프로젝트 설명서
  • main 브랜치의 커밋 2개: Initial commit, "프로젝트 설명서 추가"

💡 핵심 정리

Git ≠ GitHub
커밋은 내 컴퓨터에서만 일어나고, git push를 해야 GitHub에 올라갑니다.
origin
clone하면 원본 GitHub 주소가 origin이라는 이름으로 자동 등록돼요. git remote -v로 확인합니다.
Public 저장소
