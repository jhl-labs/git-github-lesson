Step 4 · Pages 대시보드와 로그인

docs 브랜치에 올라간 data.json을 읽어 차트와 표로 보여주는 웹 페이지를 만들고, GitHub Pages로 공개합니다. 그리고 비밀번호 화면을 붙여요.

📚 시작 전 이론: 정적 호스팅과 브라우저 속 로그인

GitHub Pages는 저장소의 브랜치(또는 Actions 워크플로우가 올려 준 파일 묶음)에 있는 파일을 https://아이디.github.io/저장소이름/ 주소로 그대로 공개하는 정적 호스팅입니다. "정적"이라는 말이 이 Step의 모든 설계를 결정해요. 서버가 요청마다 프로그램을 실행하는 게 아니라, 파일을 있는 그대로 내려줄 뿐입니다.

정적 호스팅
미리 만든 파일만 내려주는 웹 호스팅. 화면을 그리는 계산은 전부 방문자의 브라우저가 JavaScript로 합니다.
Publishing source
Pages가 어디서 파일을 가져올지 정하는 설정. 브랜치(+폴더)에서 가져오거나, Actions 워크플로우가 직접 올릴 수 있어요.
fetch()
브라우저 JavaScript가 다른 파일(예: data/data.json)을 HTTP로 내려받는 함수.
sessionStorage
브라우저 탭 하나에만 값을 저장하는 공간. 탭을 닫으면 지워져요. (localStorage는 닫아도 남음)
SHA-256 해시
입력을 고정 길이 지문(64자리 16진수)으로 바꾸는 단방향 함수. 같은 입력은 항상 같은 지문이 나와요.
orphan 브랜치
부모 커밋이 없는, 기존 기록과 완전히 분리된 브랜치. docs는 소스 기록과 섞이지 않게 이렇게 만들어요.

할 수 있는 것과 없는 것

할 수 있는 것할 수 없는 것
HTML, CSS, JavaScript, 이미지, JSON 파일 서빙서버에서 코드 실행 (Python, Node 서버, DB 연결)
브라우저에서 JavaScript로 화면 그리기사용자별로 다른 응답 주기, 진짜 로그인 세션
무료, HTTPS 자동파일 접근 차단 (공개 저장소라면 모든 파일이 공개)

이 마지막 줄이 한계 장의 핵심 복선입니다.

배포 방식 두 가지와 주소 구조

Source동작이번 실습
Deploy from a branch고른 브랜치의 /(root) 또는 /docs 폴더를 그대로 공개. 사람이 그 브랜치에 push하면 자동으로 다시 배포❌ 쓰지 않음 (아래 주의 참고)
GitHub Actions워크플로우가 파일 묶음을 직접 업로드해 배포 (actions/upload-pages-artifact → actions/deploy-pages)✅ docs 브랜치 내용을 pages-deploy.yml이 배포

왜 "브랜치에서 배포"를 안 쓰나요? 봇은 GITHUB_TOKEN으로 docs 브랜치에 push하는데, GitHub은 GITHUB_TOKEN으로 push한 커밋으로는 Pages 빌드를 시작하지 않습니다(워크플로우 무한 반복을 막기 위한 공식 동작). 그래서 docs 브랜치는 "배포할 결과물 + 데이터 변경 이력"으로 쓰고, 실제 배포는 같은 실행 안에서 pages-deploy.yml 워크플로우를 불러 직접 합니다. 저장소 이름이 주소 뒤에 붙는 프로젝트 사이트(https://<아이디>.github.io/excel-dashboard/)이므로, 코드 속 경로는 /data/data.json(도메인 맨 앞)이 아니라 data/data.json(현재 위치 기준)처럼 상대 경로로 써야 깨지지 않아요.

브라우저가 데이터를 가져오는 법

const res = await fetch('data/data.json', { cache: 'no-store' });
if (res.status === 404) { /* 아직 데이터 없음 → "엑셀을 올려 주세요" 화면 */ }
const data = await res.json();   // 텍스트 JSON → JavaScript 객체

HTML 파일을 더블클릭해 file://로 열면 브라우저 보안 정책 때문에 fetch가 막힙니다. 그래서 로컬 확인 때 python -m http.server로 작은 웹 서버를 띄워요. 또 비밀번호 해시에 쓰는 crypto.subtle은 HTTPS나 localhost에서만 동작합니다. Pages는 HTTPS라 문제없어요.

비밀번호 화면의 원리 — 그리고 왜 진짜 보안이 아닌가

  1. 설정 파일에는 비밀번호 원문 대신 SHA-256 해시를 넣어 둔다.
  2. 사용자가 입력한 값을 브라우저에서 해시해 비교하고, 같으면 sessionStorage에 "로그인됨"을 표시한다.

해시는 암호화가 아닙니다. 되돌리는 열쇠가 없는 대신, 공격자가 후보 비밀번호를 하나씩 해시해 보고 같은 지문을 찾는 방식(사전 대입)으로 짧은 비밀번호는 금방 알아낼 수 있어요. 더 근본적으로, 이 검사는 화면만 가립니다. data/data.json 주소를 직접 입력하면 비밀번호 없이 데이터가 보이고, 공개 저장소의 docs 브랜치에서도 누구나 볼 수 있어요. 오늘은 원리를 배우는 학습용이고, 진짜 해결책은 한계 장에서 다룹니다.

배포에 쓰는 Git 기술: orphan 브랜치 · worktree · .nojekyll

  • orphan 브랜치 — git checkout --orphan docs로 만들면 main의 기록 없이 빈 상태에서 시작해, 배포 결과물만 깔끔하게 담깁니다.
  • git worktree — 한 저장소에서 두 번째 작업 폴더를 열어 다른 브랜치를 동시에 꺼내 두는 기능. main 폴더를 건드리지 않고 임시 폴더에서 docs를 고쳐 커밋할 수 있어요.
  • .nojekyll — "Deploy from a branch" 방식의 Pages는 기본적으로 Jekyll(정적 사이트 생성기)로 파일을 가공하는데, 이 빈 파일이 있으면 가공 없이 그대로 공개합니다(_로 시작하는 파일이 사라지는 문제도 막아요). 우리처럼 GitHub Actions로 배포하면 올린 파일이 그대로 공개되므로 사실 필요 없지만, 나중에 브랜치 배포로 바꿔도 안전하도록 넣어 둡니다.
  • CDN 캐시 — Pages는 전 세계 캐시 서버(CDN)를 거쳐 전달돼서, 새 배포 후에도 잠시(보통 몇 분) 옛 파일이 보일 수 있어요. 대시보드가 cache: 'no-store'와 주소 뒤 ?t=시각을 붙이는 이유입니다.
✅ 실습 전 셀프 체크
  • Pages에서 Python 코드를 실행할 수 없는 이유를 "정적"이라는 단어로 설명할 수 있나요?
  • SHA-256 해시와 암호화의 차이를 말할 수 있나요?
  • 비밀번호를 몰라도 데이터를 볼 수 있는 방법을 하나 이상 말할 수 있나요?
  • docs 브랜치를 orphan으로 만드는 이유를 설명할 수 있나요?

4-1. 대시보드 만들기

git switch -c feature/dashboard

4-2. 내 비밀번호로 바꾸기

config.js에는 비밀번호가 아니라 비밀번호의 SHA-256 해시를 넣습니다. 아래 생성기로 만들어 붙여넣으세요. (계산은 이 브라우저 안에서만 일어나요.)

4-3. 로컬에서 미리 보기

샘플 데이터로 화면을 먼저 확인해 봅시다. dashboard/data/는 커밋하지 않도록 주의하세요.

mkdir -p dashboard/data
python scripts/excel_to_json.py sales-2026-h1.xlsx --out dashboard/data/data.json
python -m http.server 8000 --directory dashboard
# 브라우저에서 http://localhost:8000 접속 → 확인 후
rm -r dashboard/data

완성된 모습은 완성 예시(비밀번호 gitpages2026)와 비교해 보세요.

4-4. 배포하고 Pages 켜기

  1. 먼저 Settings → Pages — Build and deployment의 Source를 GitHub Actions로 고릅니다. (배포 워크플로우가 돌기 전에 켜 둬야 첫 배포가 실패하지 않아요)
  2. main에 합치고 push — Deploy Dashboard 워크플로우가 docs 브랜치를 처음 만들고(publish job), 이어서 Pages에 배포합니다(deploy job). 
    git add .
git commit -m "비밀번호 화면과 Pages 배포 워크플로우 추가"
git switch main && git merge feature/dashboard && git push
  3. Actions 탭에서 "Deploy Dashboard" 성공 확인 — publish → deploy 두 job이 모두 초록색인지, 브랜치 목록에 docs가 생겼는지 보세요. deploy job 옆에 Pages 주소 링크가 표시됩니다.
  4. 주소 접속 — https://<아이디>.github.io/excel-dashboard/. 아직 데이터가 없어 "엑셀을 올려 주세요" 화면이 나오면 정상!
🔁 지금까지의 흐름 정리 main 브랜치 = 사람이 관리하는 소스 코드 / docs 브랜치 = 봇이 만드는 배포 결과물. 브랜치는 "기능 개발용"뿐 아니라 이렇게 용도를 나누는 데도 쓰입니다.

🏁 마무리: 대시보드가 웹에 공개됐어요

data.json을 읽어 KPI·차트·표로 보여주는 정적 대시보드와 학습용 비밀번호 화면을 만들고, GitHub Pages로 처음 배포했습니다. 봇의 GITHUB_TOKEN push로는 Pages가 갱신되지 않기 때문에, Source를 GitHub Actions로 두고 pages-deploy.yml이 docs 브랜치 내용을 직접 배포하도록 했어요.

✅ 이번 Step에서 한 일

  1. 대시보드 + 배포 워크플로우 만들기 feature/dashboard 브랜치에서 프롬프트 4로 화면 파일과 Pages 배포 워크플로우를 요청했어요.
  2. 내 비밀번호 해시 넣기 해시 생성기로 SHA-256 값을 만들어 config.js의 passwordSha256에 붙여넣었어요.
  3. 로컬 미리 보기 샘플 데이터를 dashboard/data/에 만들어 python -m http.server로 확인한 뒤 지웠어요.
  4. Pages Source를 GitHub Actions로 첫 배포 전에 Settings → Pages에서 설정했어요.
  5. main에 합치고 push → 배포 확인 Deploy Dashboard의 publish → deploy job이 성공하고, Pages 주소에 "엑셀을 올려 주세요" 화면이 떴어요.

📦 만들어진 결과물

  • dashboard/index.html, app.js, style.css, config.js — 로그인 화면, KPI 카드, 막대 차트, 검색 표
  • .github/workflows/pages-deploy.yml — docs checkout → configure-pages → upload-pages-artifact → deploy-pages (재사용 워크플로우)
  • .github/workflows/deploy-dashboard.yml — dashboard/** 변경 시 publish job + deploy job
  • excel-to-dashboard.yml에 추가된 deploy job (needs: convert)
  • 새 docs 브랜치(orphan) — 대시보드 파일 + .nojekyll, 공개 주소 https://<아이디>.github.io/excel-dashboard/

💡 핵심 정리

정적 호스팅
Pages는 파일을 그대로 내려줄 뿐이고, 차트를 그리는 계산은 브라우저의 JavaScript가 fetch('data/data.json')으로 합니다.
Source = GitHub Actions
GITHUB_TOKEN으로 한 push는 Pages 빌드를 시작하지 않아요. 그래서 같은 실행 안에서 pages-deploy.yml을 불러 직접 배포합니다.
main vs docs
main은 사람이 고치는 소스, docs는 배포할 결과물과 데이터 변경 이력. orphan 브랜치라 기록이 섞이지 않아요.
상대 경로
프로젝트 사이트는 주소 뒤에 저장소 이름이 붙으니 /data/...가 아니라 data/...로 써야 해요.
해시 로그인의 한계
해시는 암호화가 아니고, 이 검사는 화면만 가립니다. data/data.json을 직접 열면 누구나 볼 수 있어요.

🔍 확인하고 넘어가기

  • Settings → Pages의 Source가 "GitHub Actions"로 되어 있다
  • Actions 탭의 "Deploy Dashboard" 실행에서 publish와 deploy job이 모두 초록색이다
  • 브랜치 목록에 docs가 있고, Pages 주소에서 비밀번호 입력 후 "엑셀을 올려 주세요" 화면이 보인다
  • dashboard/data/를 커밋하지 않았다
  • "Deploy from a branch"를 쓰지 않는 이유를 설명할 수 있다
  • 비밀번호를 몰라도 데이터를 볼 수 있는 방법을 하나 이상 말할 수 있다
